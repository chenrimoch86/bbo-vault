# bbo-vault — Black-Box Optimization & LLM Tuning Second Brain

A **general-purpose second-brain ingestion toolkit** that fetches papers and
web pages from a list, then converts them to clean markdown. Ships with a
ready-made catalogue on **black-box optimization & LLM-guided tuning** (built
around tuning ~200 registers of a C++ chain with ~1-min evals), but the
catalogue is just a TOML file — drop in your own list for any topic.

The repo contains:

1. **27 distilled markdown notes** in `vault/` — paper summaries, concept notes,
   and a recommended strategy for the BBO/LLM-tuning topic. Drop-in compatible
   with Obsidian, Logseq, or any markdown-based second brain.
2. **A generic ingestion pipeline** in `scripts/` — `download_raw.py` reads a
   TOML catalogue and fetches all listed resources; `convert_to_md.py` turns
   them into clean markdown.
3. **A default resource catalogue** at `scripts/resources.toml` covering the
   BBO/LLM-tuning topic (24 PDFs + 2 web pages). Replace it for any other
   research topic.

## Prerequisites

This project uses [`uv`](https://docs.astral.sh/uv/) — a fast Python package
manager that handles virtual environments, dependencies, and Python versions
automatically.

Install it once:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# or via pip / pipx / homebrew
pip install uv          # any of these work
brew install uv
```

Verify with `uv --version`. You don't need to install Python yourself — `uv`
will fetch a compatible interpreter the first time it needs one.

## Quick start

```bash
git clone <this-repo> bbo-vault
cd bbo-vault

# Create the venv and install dependencies (one-time, ~5 seconds)
make sync

# Run the full ingestion pipeline
make all
```

That's it. After `make all` finishes you'll have:

```
bbo-vault/
├── vault/                     ← 27 hand-written distilled notes (already there)
├── scripts/
│   ├── raw/
│   │   ├── papers/            ← 24 PDFs (arXiv, etc.)
│   │   ├── articles/          ← 2 HTML pages
│   │   └── _manifest.csv      ← index with URLs and statuses
│   └── raw-md/
│       ├── papers/            ← same 24 papers as markdown
│       ├── articles/          ← web pages as markdown
│       └── _conversion_log.csv
```

## Make targets

| Command | What it does |
|---|---|
| `make help`       | List all targets |
| `make sync`       | Create `.venv` and install deps from `pyproject.toml` (creates `uv.lock` if missing) |
| `make all`        | Download + convert |
| `make download`   | Just fetch raw sources into `scripts/raw/` |
| `make convert`    | Just convert `scripts/raw/` to markdown in `scripts/raw-md/` |
| `make lock`       | Refresh `uv.lock` from `pyproject.toml` (after editing deps) |
| `make clean`      | Remove `raw/` and `raw-md/` (keeps `vault/` notes safe) |

Useful variables:

```bash
make download TIER=1     # only the 6 must-have papers (Tier 1)
make download TIER=2     # Tier 1 + Tier 2 nice-to-haves
make UV=/path/to/uv all  # override the uv binary
```

## Running scripts directly (no Makefile)

The scripts use [PEP 723 inline metadata](https://peps.python.org/pep-0723/),
so `uv run` will auto-create an ephemeral environment with the right deps —
**you don't even need `make sync` first** for this:

```bash
# Run the download script (no deps needed, but uv handles it anyway)
uv run scripts/download_raw.py

# Run the conversion script (uv installs pymupdf4llm + trafilatura on the fly)
uv run scripts/convert_to_md.py --in scripts/raw --out scripts/raw-md
```

If you've already run `make sync`, the project venv at `.venv/` is used
instead — faster on repeated invocations. Both styles work; `make sync` once
plus `make all` is the most ergonomic for daily use.

## Using it for any topic (not just BBO)

The download script reads a **TOML catalogue** of resources. The bundled
`scripts/resources.toml` covers black-box optimization, but the format is
generic — point it at any list:

```bash
# Generate a starter catalogue for a new topic
uv run scripts/download_raw.py --init my-topic.toml

# Edit my-topic.toml: each entry is one paper or page
# Then run the pipeline against it
uv run scripts/download_raw.py --resources my-topic.toml --out raw
uv run scripts/convert_to_md.py --in raw --out raw-md
```

The schema is intentionally minimal:

```toml
[[resource]]
tier     = 1                          # 1=must-have, 2=nice, 3=ref (any int)
kind     = "pdf"                      # "pdf" or "html"
filename = "Author-Year-Title.pdf"    # local filename
url      = "https://arxiv.org/pdf/..."
note     = "One-line description"     # optional, used in manifest
```

`tier` is just a filter. `download_raw.py --tier 1` fetches only must-haves,
`--tier 2` adds nice-to-haves, etc. Use whatever convention works for you.

## Adopting it as your second brain

The **`vault/`** folder is itself a self-contained Obsidian vault. Open
Obsidian, choose "Open folder as vault", and point it at `vault/`. All
wikilinks (`[[Note Name]]`) resolve immediately.

If you want the converted papers to live in the same vault, move
`scripts/raw-md/` into `vault/` after conversion — for example as
`vault/06-Sources/`. Each converted paper has YAML frontmatter pointing at the
original URL, so cross-references between distilled notes and raw sources stay
explicit.

## What each script does

### `scripts/download_raw.py`

Reads a TOML catalogue (default: `scripts/resources.toml`) and fetches each
listed resource into `raw/papers/` (PDFs) or `raw/articles/` (HTML). Pure
Python stdlib — no third-party dependencies. Idempotent (skips existing
files). Writes `_manifest.csv` with URL, status, and description per file.

```bash
uv run scripts/download_raw.py                       # use default catalogue
uv run scripts/download_raw.py --tier 1              # only must-haves
uv run scripts/download_raw.py --resources my.toml   # custom catalogue
uv run scripts/download_raw.py --init my.toml        # create starter template
uv run scripts/download_raw.py --skip-html           # PDFs only
uv run scripts/download_raw.py --dry-run             # preview, don't fetch
uv run scripts/download_raw.py --help                # full options
```

### `scripts/convert_to_md.py`

Walks `raw/` and writes markdown copies to `raw-md/`. Tries the highest-quality
converter available, falls back gracefully:

| Source | Best tool      | Fallback 1     | Fallback 2 |
|--------|----------------|----------------|------------|
| PDF    | `pymupdf4llm`  | `pypdf`        | `pdftotext` (system) |
| HTML   | `trafilatura`  | `markdownify`  | stdlib HTML stripper |

Each output `.md` gets YAML frontmatter pulled from `_manifest.csv` (title,
source URL, description, conversion method, date).

```bash
uv run scripts/convert_to_md.py             # default: ./raw -> ./raw-md
uv run scripts/convert_to_md.py --force     # re-convert existing .md files
uv run scripts/convert_to_md.py --dry-run   # preview
```

## Re-running and updating

Both scripts are idempotent:

- `download_raw.py` skips files that already exist on disk. Use `--force` to
  re-download.
- `convert_to_md.py` skips `.md` files that already exist. Use `--force` to
  re-convert.

This means you can re-run `make all` any time without wasting bandwidth or
clobbering work — useful when adding new entries to `RESOURCES` in
`download_raw.py`.

## Adding new papers

Edit `scripts/resources.toml` and append:

```toml
[[resource]]
tier     = 2
kind     = "pdf"
filename = "Author-Year-ShortTitle.pdf"
url      = "https://arxiv.org/pdf/XXXX.XXXXX"
note     = "Short description for the manifest"
```

Then re-run `make all`. The new paper will be downloaded and converted; all
existing files are skipped.

## Adding new dependencies

If you extend the scripts and need new packages:

```bash
uv add somepackage           # adds to pyproject.toml + updates lock + venv
uv add --dev pytest          # dev-only dependency
uv remove somepackage        # remove
uv tree                      # see the full dep tree
```
